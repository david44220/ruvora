# Internationalization

Ruvora supports English (`en`) and French (`fr`) through the dictionaries in `src/i18n/messages.ts` and the application's locale helpers. A React context exposes the selected messages; the `ruvora_locale` cookie persists the choice for one year. The server layout reads that cookie for the initial locale.

All user-facing interface copy belongs in these dictionaries: navigation, forms, button labels, status values, empty states, accessibility labels, errors and economic explanations. Creator-authored bios, campaign content, handles and external content are not automatically translated.

## Contract

- Every English key must have a French translation. Keep message key parity type-checked.
- Locale switching must be visible and keyboard accessible, and preference must persist across navigation/reload through the locale provider's documented persistence mechanism.
- Server rendering and client initialization should agree on the initial locale to avoid hydration differences.
- Format numbers, money and dates with the selected locale; do not concatenate currency symbols onto floating-point values.
- Backend errors expose stable machine codes. The presentation layer maps those codes to translated user-facing copy; internal diagnostic messages are not the translation source.
- Layouts must withstand longer French phrases, wrapping labels and mobile input widths.
- Accessible labels, image descriptions, metadata and share actions require the same review as visible copy.

## Terminology

| Concept                      | English           | French                                         |
| ---------------------------- | ----------------- | ---------------------------------------------- |
| Brand                        | Ruvora            | Ruvora                                         |
| Eligible period contribution | Reward Units / RU | Reward Units / RU                              |
| Long-term progression        | Experience / XP   | Expérience / XP                                |
| Event ranking score          | Event Points      | Points d’événement                             |
| Monetary record              | Ledger            | Registre                                       |
| Audience provenance          | Self-declared     | Déclarée / non vérifiée par une source externe |

Translations must preserve economic meaning: RU is not money or crypto and has no guaranteed fixed monetary value. XP and Event Points are separate systems. Creator threshold access does not promise income. Development balances and credits must remain visibly simulated in both languages.

## Adding a message or locale

Add a stable semantic key to the source dictionary and its counterpart to French. Reuse the locale hook/helper instead of importing one language directly into UI components. Avoid sentence fragments that depend on English word order. Use parameters for dynamic values while keeping the whole sentence translatable.

Before adding a locale, define number/date conventions, fallback behavior, persistence, metadata and layout direction, then validate representative forms and financial explanations.

## Validation

Run the dictionary/key-parity unit checks, typecheck and browser journeys. Manually inspect homepage, auth/onboarding, public profiles, dashboards, campaign form, event ranking and admin errors in both languages. Record the actual coverage in [RELEASE_REPORT.md](RELEASE_REPORT.md); the existence of dictionaries alone is not full localization verification.
